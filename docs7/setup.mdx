Set up the tutorial in your own fork before working through the exercises.
Run terminal commands from a checkout of the repository. Prompts beginning
with a slash belong in Copilot chat.

## Codespaces and the installer

The exercises run in GitHub Codespaces, which installs the tooling for you.
The repository ships a dev container per exercise, for example
`.devcontainer/devcontainer.json` and
`.devcontainer/attach-images-to-an-issue/devcontainer.json`. You need a
GitHub account with access to your fork and permission to create Codespaces
for it.

Each dev container uses the `mcr.microsoft.com/devcontainers/base:ubuntu`
image with the `github-cli` feature and runs
`.devcontainer/setup.sh` through its `onCreateCommand`.

The installer checks whether the `github/gh-stack` extension is already
installed and installs it only if missing. It also sets
`rerere.enabled=true` and `remote.pushDefault=origin` globally.

Each dev container invokes the setup script during environment creation.
When GitHub creates a Codespaces prebuild for the relevant repository,
branch, and dev container configuration, it runs this command before
saving the container snapshot. Prebuild configuration and a ready prebuild
have not been independently verified for this repository.

The stack exercise relies on `gh-stack`. The script sets the push default
to `origin`; confirm that `origin` points to your fork before submitting.

Verify the installer result in the Codespace terminal:

```bash
gh --version
gh extension list
gh stack --help
git config --global --get rerere.enabled
git config --global --get remote.pushDefault
```

The Git settings above should print `true` and `origin`, respectively.
These checks verify the current environment, not whether a prebuild was used.

For a verification record, include `git rev-parse HEAD`, the selected dev
container configuration path, and the command outputs. Keep creation-log
confirmation of `onCreateCommand` separate from the resulting tool and Git
settings; those outputs alone do not establish which lifecycle command ran.

Stop the Codespace when you finish testing. Stopping retains its files;
delete a disposable Codespace separately when you no longer need it.

If `gh extension list` does not show `github/gh-stack`, run the installer
from the repository root:

```bash
bash .devcontainer/setup.sh
```

### Run the exercises locally

Prefer your own machine? Install the same pieces:

- [GitHub CLI](https://cli.github.com) (`gh`)
- [`gh-stack`](https://github.com/github/gh-stack), installed by the setup
  script if it is missing
- Git, for the `rerere` and `remote.pushDefault` settings

Complete the GitHub CLI sign-in steps below if needed. Clone your fork,
then run the installer from the repository root:

```bash
bash .devcontainer/setup.sh
```

## GitHub CLI

### 1. Sign in

For the tutorial's interactive web login, clear token overrides in this
terminal and start authentication:

```bash
unset GH_TOKEN GITHUB_TOKEN
gh auth login --hostname github.com --git-protocol https --web
```

Complete authorization in the browser and wait for the terminal prompt to
return. Then check the signed-in account:

```bash
gh auth status --hostname github.com
```

The `unset` command affects this shell only. Use this interactive flow in
your development terminal; automation may use its existing token configuration.

### 2. Choose your fork

**If you already use RepoKan/virtual-universe-26**, skip fork creation. From
its local checkout, check the remote before setting the defaults:

```bash
git remote -v
gh auth setup-git
gh repo set-default RepoKan/virtual-universe-26
gh repo set-default --view
gh repo edit RepoKan/virtual-universe-26 --enable-issues
```

Confirm that your working checkout and push remote point to the intended
fork before creating issues or pushing changes.

**If you are starting from the upstream tutorial and do not have a fork**,
run the original setup sequence after signing in:

```bash
gh auth setup-git &&
gh repo fork --remote --remote-name origin &&
gh repo set-default origin
```

Check the remote and selected default repository before continuing:

```bash
git remote -v
gh repo set-default --view
```

Confirm that `origin` and the selected default repository identify your fork.
Then enable issues on that fork:

```bash
gh repo edit --enable-issues
```

To copy a command on GitHub, hover over its code block and click the copy
button at the top right. In a Codespace, press **Ctrl + backtick** to toggle
the terminal.

## Copilot and Context7

The Copilot learning path is **Skills → Tools and connectors → Security
review → Automate**. The following instructions use the Copilot app UI.
Other clients can have different menus, agent support, and MCP configuration.

### 1. Find the documentation agent

Paste this into Copilot chat:

```text
/agentfinder find the Context7 Expert custom agent in github/awesome-copilot for looking up current library documentation
```

Review the result. You can inspect the
[Context7 Expert agent source](https://github.com/github/awesome-copilot/blob/main/agents/context7.agent.md)
before adding it. Search results and agent compatibility can vary.

### 2. Add the agent

Paste this into Copilot chat:

```text
Add the Context7 Expert agent from github/awesome-copilot to this project. Check compatibility with this app and use the keyless Context7 connector with its current resolve-library-id and query-docs tools. Ask before installing or changing its configuration. Keep this session open.
```

Confirm that the installed agent uses the connector's currently exposed
tools, `resolve-library-id` and `query-docs`. If the source still refers to
an older tool such as `get-library-docs`, review the compatibility change
before applying it.

### 3. Add the Context7 MCP connector

In the Copilot app:

1. Open **Customize** at the top of the sessions sidebar.
2. Search for **Context7**, select the server, and choose **Add server**.
3. Select **HTTP** and review the default settings.
4. Return to your session.

The remote MCP endpoint is `https://mcp.context7.com/mcp`. The repository
tutorial reports that it was tested without an API key; keyless availability,
rate limits, and app or organization policy can vary. Check the
[current Context7 client instructions](https://context7.com/docs/resources/all-clients)
if authentication is requested. Never paste credentials into a public issue,
pull request, or documentation page.

Test the agent and connector with a public documentation query:

```text
Use the Context7 Expert agent and the Context7 MCP connector to find how Node.js reads a UTF-8 file with node:fs/promises. Show a short example and its documentation source. Send only this public documentation query, not repository contents. If the agent or connector isn't available in this session, tell me; don't substitute web search.
```

Look for an actual Context7 tool call and a linked Node.js documentation
source. Installing a connector does not prove that a lookup succeeded.

### 4. Use documentation lookup in the skill

Open `.github/skills/issue-to-pr/SKILL.md` and add this before the step that
makes the fix:

```markdown
When a fix needs library or API documentation, use the Context7 Expert
agent and Context7 MCP connector to look it up. Send only public
documentation queries, not repository contents. Cite relevant sources
in the draft PR. If the agent or connector is unavailable, report it
instead of claiming the lookup succeeded.
```

Alternatively, ask Copilot to prepare the edit:

```text
Update .github/skills/issue-to-pr/SKILL.md to use the Context7 Expert agent and connector when a fix needs library or API documentation. Send only public documentation queries, cite relevant sources in the draft PR, and report unavailable tools instead of pretending a lookup succeeded. Show me the edit; don't commit or push yet.
```

Review the edit before proceeding with your exercise. A documentation lookup
does not replace project tests or a security review.
